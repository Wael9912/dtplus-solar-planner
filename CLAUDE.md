# DT+ Solar Planner — notes for Claude

- Stack: Vite 8 + React 19 + TypeScript + Tailwind v4 (`@tailwindcss/vite`), zustand (persisted to localStorage), recharts, exceljs, jspdf + jspdf-autotable. No backend.
- `src/engine/compute.ts` is the single source of truth for all calculations (BOM in `bom.ts`, economics in `economics.ts`, monthly tilt model in `irradiance.ts`); UI components only render `Results`. Every money figure on screen, in the PDFs and in Excel comes from `buildQuote()` in `src/engine/quote.ts` (display currency, rounded lines; `pricing.marginPct` is markup on cost). The client proposal shows sell prices only — never cost or markup. Formulas follow `docs/sizing-methodology.md` — update the doc if you change a formula.
- Data: `src/data/catalog.ts`, `appliances.ts`, `locations.ts` are generated from research JSON (keep them as plain arrays; edit directly). `items.ts` holds balance-of-system items referenced by id from `buildBom()`.
- Tailwind v4: custom classes cannot be composed with `@apply` of other custom classes — share base styles with grouped selectors (see `src/index.css`).
- i18n: `src/i18n/en.ts` is the type source (`Dict`); `ar.ts` must have the same keys. Engine checks carry `messageAr` + `step`; BOM lines carry `nameAr`/`specAr`; city names live in `src/i18n/places.ts`. Export strings live in `src/export/labels.ts`. PDFs support Arabic via the embedded IBM Plex Sans Arabic font (`src/export/fonts/`, lazy-loaded; run all PDF text through `pdfkit.ts` helpers).
- Modes (v0.2, methodology §16): `Project.mode` = `design` | `size` | `items` (missing → design); `MODE_STEPS` in `src/components/wizardModel.ts` decides the wizard steps. `Project.sizing` (`src/engine/sizing.ts`): demand from loads or bill, fixed sizes (`pvKwp` 0 = backup-only, `batteryKwh` 0 = none), existing equipment. The load calculator is the store's `calc` scratch project (`#/calc`); engineering tools are pure functions in `src/engine/tools.ts` (`#/tools/<id>`).
- Company price list: `company.priceBook` (prices USD by id, hidden ids, own products `my-…`) is applied by `computeProject(p, book)` through `src/engine/catalogContext.ts` (`cat()` lookups, `avail()` auto-selection). UI must get results via `useComputed()` and product lists via `useCatalog()` (`src/components/useEngine.ts`) — never import `catalog` in UI or call computeProject without the book.
- Quotes that leave Draft carry `lockedPrices` (frozen company price list) — `computeProject` prefers it over the book it is given; the store's `updateProject` locks/unlocks on status changes. Imported / stored projects pass through `normalizeProject`, which coerces every field by type; keep it in step with new fields.
- Client documents never print the placeholder company name or a default project title, and print `proposalNote` (never the internal `notes`); company Arabic fields `nameAr`/`taglineAr`/`termsAr` feed Arabic documents (`localizeCompany`).
- Screens (v0.3): `home` (`#/home`, the landing screen, `HomePage.tsx`) shows every feature as a tile grouped by use — calculators (load calculator + each engineering tool), quotes & proposals (size / items / design), history & company — plus recent work. `projects` (`#/projects`, alias `#/history`, `ProjectsPage.tsx`) is the History list; the header History button (`nav-projects`) is visible on phones too, except inside a project where the back arrow leads there. New features need a home tile.
- Installable app (PWA): `public/manifest.webmanifest`, icons from `scripts/make-icons.mjs`, service worker template `pwa/sw.js` → the `serviceWorker()` plugin in `vite.config.ts` writes `dist/sw.js` with the build id and every build file (precached; network-first app page with a 4 s fallback; `version.json` and `sw.js` never cached, so `src/updates.ts` keeps working). `src/pwa.ts` registers it (production only) and holds the install prompt; UI in `components/InstallApp.tsx`. E2E: `node tests/e2e/pwa.mjs` (builds twice, own server on :5182: installability via DevTools, offline with the server down incl. PDF/Excel, cache swap on a new build).
- Saving: the store persists through `savingStorage` (`src/store/useSaveState.ts`); a refused write (storage full, ≈5 MB) shows `SaveBanner` and "Not saved" in the wizard until a save works. Logos are shrunk to ≤ 600 px on upload (`components/logo.ts`).
- E2E: `npx vite --port 5179 --strictPort &` then `LANES=3 node tests/e2e/run-all.mjs` (≈15 min; scenario 21 needs a v0.1 build, see the header of `tests/e2e/21-migrate.mjs`). Fuzz: `tests/stress.test.ts` (projects) and `tests/tools-stress.test.ts` (engineering tools), both honour `STRESS_SEED`, `STRESS_N`. Scenario 25 checks a 600-project history, logo shrinking and storage-full.
- App updates (`src/updates.ts`): every build writes `dist/version.json` with a build id; open copies of the app check it on start, on returning to the tab, when back online and every 15 min, reload by themselves when nothing is in progress (banner while typing / a dialog is open) and then show the release notes from `src/i18n/updates.ts` (`notes` keyed by package.json version, EN + AR). When releasing: bump `version` in package.json and add notes for it (`tests/updates.test.ts` fails otherwise), and raise `NOTES_SINCE_0_1` in `tests/e2e/update-flow.mjs` by the new notes. E2E for the flow: `node tests/e2e/update-flow.mjs` (builds twice, own server on :5181, chromium + iPhone WebKit).
- i18n modules: besides en.ts/ar.ts, module strings live in `src/i18n/{tools,calc,prices,inputs,outputs}.ts` (`t.tools`, `t.calc`, …), each with an En type source and a matching Ar object.
- Tests: `npx vitest run` (tests/). Fixtures come from §13 of the methodology doc; note the doc's example (a) mis-adds connected load (410 W, not 420 W).
- Deploy: Cloudflare Pages only (GitHub Pages retired 2026-11-01). Manual: `npm run deploy` (`deploy:cf` is an alias); pushing to `main` does not deploy. `base` is `/` (override with `VITE_BASE`); routing is hash-based. Live at https://dtplus-solar-planner.pages.dev (classic Pages project, account digitaltransformationplus@gmail.com). Wrangler 4.15x turns `pages project create` into a Workers project and rewrites `vite.config.ts`/`package.json` unless `--force` is passed — the project already exists, so don't recreate it.
